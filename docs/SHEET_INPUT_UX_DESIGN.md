# 会計集計スプレッドシート 入力UX改善設計書

対象: 「柿川亭・アブララボ 会計集計」Googleスプレッドシート（`docs/DATA_MODEL.md` 準拠）
役割の再確認: 閲覧・分析は「ジョー」（`docs/APP_DESIGN.md`）が担当。このシートの役目は**原簿＝毎日の入力**のみ。
ゴール: 「毎日の入力が速い・間違えにくい・迷わない」。分析用の凝った表はこのシートには増やさない。

masaから届いた最優先の不満2点を、本設計の中心に据える。

---

## 0. 最優先で解決する2点

### ①タブ移動がつらい（特にスマホ）

Googleスプレッドシートアプリはタブが画面下部に横並びで、目的のタブまで延々スクロールする必要がある。現状タブは概算9枚（使い方／設定／日次_柿川亭／日次_アブララボ／メニュー_柿川亭／メニュー_アブララボ／仕入経費／人件費／月次集計）あり、しかも毎日触るタブと月1回しか触らないタブが同列に並んでいるため、迷いながらスクロールすることになる。

**解決の柱（詳細は2-1）**
- 毎日は触らないタブ（使い方／設定／月次集計／未稼働のメニュー_アブララボ）を**非表示化**し、常時表示するタブを5枚まで削減
- 残るタブを**入力の作業順**に並べ替え（使い方タブの手順そのまま＝迷う余地をなくす）
- 先頭に**「📋入力ハブ」タブを新設**し、今日の入力状況チェック＋各タブへのジャンプ導線を1画面に集約
- 各シートを**新しい日付が一番上（逆時系列）**に並ぶ設計に変更し、「今日入力する行」が常に同じ位置（見出し直下）に来るようにする＝タブの中でも迷わない

### ②税区分×税率の指定がわかりにくい（仕入経費タブ）

「税抜/税込」と「8%/10%」を毎行2セル別々に選ぶ必要があり、直感的でなくミスの元。

**解決の柱（詳細は2-2）**
- 「税抜/税込」×「8%/10%」を**1つのドロップダウン（税込8%／税込10%／税抜8%／税抜10%）に統合**
- 既存の税抜金額／消費税／税込金額の計算式は**一切変更せず**、統合ドロップダウンの選択を裏側で自動的に旧2列（税区分・税率）へ分解する数式に差し替える（壊れないリファクタ）
- 仕入先ごとに「いつもの税区分・税率」を設定タブに登録しておき、**選んだ内容が仕入先の通常パターンと違えば警告**（例：東北電力なのに8%を選んだ、めんつうなのに税抜10%を選んだ、など）
- レシートの見分け方をヘッダーのノート（コメント）と使い方タブに常設

## 2. 改善設計

### 2-1. タブ移動の負担削減（最優先①）

**A. 常時表示タブを5枚に絞る（非表示化）**

Googleスプレッドシートは「シートを非表示」機能があり、非表示にしたシートはタブバーに表示されなくなる（メニューからいつでも再表示可能・データは消えない）。これを使い、毎日触らないタブを隠す。

| タブ | 表示/非表示 | 理由 |
|---|---|---|
| 📋入力ハブ（新設） | 常時表示・先頭 | 毎日最初に開く場所 |
| 🍜日次_柿川亭 | 常時表示 | 毎日入力 |
| 🧴日次_アブララボ | 常時表示 | 稼働後は毎日入力（今は薄いが残す） |
| 🍜メニュー_柿川亭 | 常時表示 | 毎日入力 |
| 🧾仕入経費 | 常時表示 | 伝票がある日に入力（頻度高） |
| 👤人件費 | 常時表示 | ほぼ毎日入力 |
| ⚙設定 | **非表示**（月替わりのみ表示） | 月1回しか触らない |
| 📖使い方 | **非表示**（困った時だけ表示） | オンボード後は不要 |
| 📊月次集計 | **非表示**（ジョーが分析担当のため確認頻度低） | 検算用に残すが毎日は不要 |
| 🧴メニュー_アブララボ | **非表示**（POSメニュー確定まで） | 未稼働 |

→ タブバーが9枚→**5枚**に。スマホでの横スクロール量は半分以下になる。

**B. タブの並び順を「入力する順番」に統一**

使い方タブに書かれている入力フロー（日次→メニュー→仕入経費→人件費）と、タブの物理的な並び順を完全に一致させる。「次にどれを触ればいいか」を考えなくても、左から右に触っていけば完了する状態にする。

**C. タブ名を短く・絵文字プレフィックス付きに**

小さいタブ幅でも一瞄で判別できるよう、タブ名を絵文字＋短縮名にする（例：`📋入力ハブ` `🍜日次:柿川亭` `🧴日次:アブラボ` `🍜メニュー:柿川亭` `🧾仕入経費` `👤人件費`）。絵文字は「文字を読む」前に「形で見分ける」ためのショートカットとして機能する。

**D. タブに色をつけてグルーピング**（シートタブを右クリック→色を変更）
- 入力ハブ＝紺
- 日次_柿川亭／メニュー_柿川亭＝柿川亭の識別色（ジョーと合わせて青系）
- 日次_アブララボ＝アブララボの識別色（オレンジ系）
- 仕入経費／人件費＝グレー系（店舗横断のため中立色）

**E. 「今日入力する行」を常に同じ位置に固定する（新しい日付が上）**

現在は日付昇順（下に追記）と推測されるため、月が進むほど今日の行がどんどん下に潜っていく。これを**日付の新しい順（降順）**に変更し、レイアウトを次のようにする。

```
1行目: 見出し（固定）
2行目: 月次小計（固定・現在シート末尾にあるものをここへ移動）
3行目: 今日（＝一番新しい日付）の入力行 ← 常にここ
4行目以降: 過去の日付が古い順に下へ続く
```

「見出し＋小計」の2行をセットで固定（表示→固定→2行）すれば、シートを開いた瞬間に必ず「入力すべき行」が画面内に見えている状態になる。スクロールがほぼ不要になる。
※ジョー側のgvizデータ取得は列をヘッダー名で参照する設計（`docs/APP_DESIGN.md` 記載）のため、行の並び順を変えてもジョーの表示には影響しない。ただし月次小計行の位置が変わるため、**Codex実装時に月次集計タブ・ジョー側で月次小計行を除外している既存ロジックがあれば、行位置の変更に合わせて調整が必要**（要確認）。

**F. 入力ハブタブの中身**

1枚に「今日やることリスト」を集約する。

```
┌─────────────────────────────────────┐
│ 📋 今日の入力（2026/07/23 水）             │
├─────────────────────────────────────┤
│ ⬜ 日次_柿川亭        [▶ 開く]           │
│ ⬜ 日次_アブララボ     [▶ 開く]           │
│ ⬜ メニュー_柿川亭     [▶ 開く]           │
│ ⬜（本日レシートなければ省略可）仕入経費 [▶ 開く]│
│ ⬜（本日出勤者なければ省略可）人件費   [▶ 開く]│
├─────────────────────────────────────┤
│ ⚠ 設定タブの対象月と今日の月が違います（要確認）│  ← 月またぎ時のみ表示
└─────────────────────────────────────┘
```
- チェック（⬜→✅）は各タブの「今日の日付の行」に必須項目が入っているかを自動判定する数式（例：日次シートの2行目〈=今日〉の日付が今日と一致し、かつ主要項目が空でなければ✅）
- `[▶ 開く]` は `=HYPERLINK("#gid=<各タブのgid>", "▶ 開く")` でジャンプボタン化。各タブ側は上記Eの「新しい日付が常に上」設計により、ジャンプ先で追加スクロールせず即入力できる
- 月またぎ警告は `=IF(MONTH(TODAY())<>設定!対象月セル, "⚠ 設定タブの対象月を更新してください", "")` のような数式で常時監視

### 2-2. 税区分×税率の統合（最優先②）

**A. 統合ドロップダウンに一本化**

仕入経費タブの「税区分」列と「税率」列を廃止し、代わりに**「税区分・税率」列を1つ新設**（仕入先・費目の右、入力額の左に配置）。データの入力規則でプルダウンリストを設定：

```
税込8%
税込10%
税抜8%
税抜10%
```

短い4択のみで、選択肢自体には説明文をつけない（スマホのドロップダウンは選択肢が長いとタップしづらいため）。意味の説明はヘッダーセルの**ノート（コメント）**と使い方タブに常設する。

**B. 既存の計算式を壊さない裏側の作り**

「税抜金額／消費税／税込金額」の計算式は現状のまま**税区分セル・税率セルを参照している前提**なので、それらのセルを削除せず「自動計算セル」に変える。

- 旧「税区分」列 → 数式化：`=IF(LEFT([税区分・税率],2)="税込","税込","税抜")`
- 旧「税率」列 → 数式化：`=IF(RIGHT([税区分・税率],3)="10%",10%,8%)`
- 列の色を黄（手入力）→緑（自動計算）に変更し、保護をかける
- 必要なら2列とも列を右端や末尾に「補助列」として移動し、通常はグループ化で折りたたんでおく（触らせない）

これにより、**入力するのは新しい1セルだけ**になり、以降の税抜/税込/消費税額の計算は一切変更なしでそのまま動く。

**C. レシートの見方ガイド（ノート／使い方タブに常設）**

```
【税区分・税率の選び方】
・レシート/伝票に「税込」「内税」と書いてある、または金額の後ろに(税込)表記
　→ 税込8% or 税込10%
・業者の請求書・伝票で「税抜金額」が別途明記されている
　→ 税抜8% or 税抜10%
・8%か10%か迷ったら：食品・飲料（酒類・外食を除く）＝8%／それ以外
（電気・ガス・消耗品・資材・外食等）＝10%
```

**D. 仕入先ごとの既定パターンを設定タブに登録し、選び間違いを検知**

設定タブに「仕入先ごとの既定税区分・税率」対応表を追加（下表はたたき台。実際の運用に合わせてmasaに確認・修正してもらう前提）：

| 仕入先 | 既定の税区分・税率（想定） |
|---|---|
| めんつう | 税込8% |
| ホクショク | 税込8% |
| 中越鶏卵 | 税込8% |
| マルヤマ包装 | 税抜10% |
| 竹内農園 | 税込8% |
| アルベーロ | 税込8% |
| スーパー | 税込8% |
| 北陸ガス | 税抜10% |
| 東北電力 | 税抜10% |
| その他 | （提案なし） |

仕入経費タブに「提案（参考）」列を追加：`=VLOOKUP([仕入先・費目], 設定!仕入先税区分表, 2, FALSE)`。実際の選択と提案が食い違う行を条件付き書式で薄オレンジ表示（ブロックはしない＝例外はあるので警告どまり）。

**E. 選び忘れ・矛盾の条件付き書式**
- 入力額が入っているのに「税区分・税率」が空欄 → 赤背景（必須未入力エラー）
- 「税区分・税率」の選択が上記Dの提案と不一致 → 薄オレンジ背景（要確認）
- 税込金額 ≠ 税抜金額＋消費税（通常は式で一致するはずだが、手動上書き等で崩れた場合の保険）→ 赤字＋太字

### 2-3. その他の入力を速く・ミスを減らす具体策

**ドロップダウン化する項目一覧**

| タブ | 列 | リスト元 |
|---|---|---|
| 日次_各店 | （曜日は手入力させず自動化） | `=TEXT(日付,"aaa")` |
| メニュー入力 | （数値のみ、負の数を弾く） | データの入力規則：0以上の整数 |
| 仕入経費 | 仕入先・費目 | 設定タブの仕入先リストをプルダウン化（自由入力欄を廃止し表記ゆれを根絶） |
| 仕入経費 | 税区分・税率 | 上記2-2の4択 |
| 仕入経費 | 支払方法 | 現金／カード／振込／その他 の4択プルダウンを新設 |
| 人件費 | 氏名 | 設定タブに「スタッフ名簿」を追加しプルダウン化（表記ゆれ防止、ジョーのスタッフ別集計の精度に直結） |
| 人件費 | 出勤／退勤 | データの入力規則で時刻形式を強制。可能ならスタッフごとの定時をデフォルト値として行複製時に引き継ぐ運用ルールにする |
| 全タブ | 日付 | データの入力規則「日付」を設定し、スマホでカレンダーピッカーが出るようにする |

**日次シートの二重入力を解消（現状課題#6の対応）**

日次_柿川亭の「券売機杯数」を手入力ではなく `=VLOOKUP(日付, メニュー_柿川亭!日付列:純販売数合計列, 対応列, FALSE)` で自動反映に変更。メニュー入力さえ済ませれば日次側は何もしなくてよくなる＝入力の手間が1項目まるごと消える。

**差額確認列の明確化（現状課題#7の対応）**
- 列名を「差額確認（封筒とレシートの差）」のように具体化
- 0以外の場合は条件付き書式で赤背景＋太字にして見逃さないようにする
- ヘッダーにノートで「日次シートの券売機売上（封筒記載）とメニュー_柿川亭の券売機売上（レシート集計）の差。0以外なら封筒かレシートの読み取りミスを疑う」と説明

**月またぎ検知（現状課題#9の対応）**

入力ハブ（2-1のF）に警告表示。加えて設定タブ自体にも `=IF(MONTH(TODAY())<>対象月, "⚠今月分に更新してください", "✓最新")` のセルを常設し、非表示にしていても入力ハブ経由で異常だけは検知できるようにする。

### 2-4. 手入力/自動計算の視覚区別と保護

- 色ルールを全タブで統一：**手入力＝淡い黄色背景**／**自動計算＝淡い緑背景＋グレーがかった文字色（触るな感を出す）**／**要確認・警告＝淡い赤orオレンジ背景**
- 自動計算列（売上合計、券売機杯数(VLOOKUP化後)、換算人数各種、推定来店客数、税抜金額/消費税/税込金額、勤務時間、人件費、純販売数合計、月次小計・月次集計タブ全体）に「シートの保護」→「範囲を保護」をかけ、**警告付き保護**（編集しようとすると確認ダイアログが出る＝完全ロックではなく事故防止のブレーキ）に設定。masaが唯一の編集者かつCodexも定期的に列を触るため、厳格ロックではなく警告レベルが現実的
- 凡例ミニ表を各タブの右上（フリーズ範囲の外・一等地）に小さく常設：「🟡入力 🟢自動 🔴要確認」

### 2-5. スマホ対応の追加工夫

- 全タブで「見出し行の固定」＋「先頭列（日付）の固定」を必須設定（表示→固定）
- 入力する列は左から右への一直線の入力順に揃え、Tabキー（スマホは次へボタン）での移動だけで完結するようにする
- 行の高さを標準よりやや広め（21px→24px程度）にし、指でのタップ判定を大きくする
- フィルタ表示（フィルタビュー）で「今月分のみ」を用意しておくと、過去月データが視界に入らずスマホでの誤タップ・誤スクロールが減る

### 2-6. メニュー約40項目入力の負担軽減

現実的な範囲での対策（表形式自体は維持するのが最速という判断。券売機レシートを見ながらの転記作業には、Googleフォーム化などで1問1答にするより「一覧表を上から埋める」方が速いため）。

1. **列を頻出順に並べ替え**：油そば並/大/特盛りなど毎日ほぼ必ず数字が入る主力商品を左側（＝見出し固定範囲のすぐ右）にまとめ、季節商品・ギフトセットなど頻度の低い列は右側に寄せる

6. PC入力を基本線とし、スマホは確認・軽微修正のみという運用ルールを使い方タブに明記（無理に全てをスマホ最適化しない）
